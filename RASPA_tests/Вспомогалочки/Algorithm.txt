run.sh — Главный скрипт запуска (Менеджер) - запускаем только его:
- Связывает все этапы воедино.
- Копирует необходимые файлы в рабочую зону.
- Создает рабочий файл simulation.input из шаблона simulation.input.template (чтобы каждый раз вместо REPLACE_ME подставлялся нужный нам газ).
- Запускает RASPA и убирает временные файлы после расчета.

convert_to_raspa.py — Скрипт обработки (Рабочий):
- Берет «грязный» .cif файл с мофом из папки MOF, чистит его от лишних данных, приводит к симметрии P1 -> получаем файл simulation_structure.cif готовый для обработки RASPA.
- Считает парциальные заряды методом PyEQEq (или ставит 0.0, если библиотека не установлена), записывает их прямо в .cif файл imulation_structure.cif.
- Ищет файл определения газа (например, CO2.def) в системной библиотеке RASPA и копирует в локальную папку ForceField, или если до этого он уже был скопирован в папку ForceField, то берет его оттуда.
Перед симуляцией из локальной папки ForceField копирует файл с газом в корень рабочей директории (Local) и после симуляции удаляет его из корня директории.

simulation.input.template — Шаблон настроек.
- Содержит параметры симуляции (температура, давление, число циклов) <- разбор можно посмотреть в simulation_input.txt.
- Вместо имени газа содержит метку REPLACE_ME, которая автоматически заменяется при запуске.

! Копирование газов и полей в рабочую директорию из стандартной библиотеки RASPA нужно для избежания ошибок при запуске симуляции !


Общий алгоритм:
1. Вход: "грязный" файл .cif с MOF
2. Шаг 1: конвертер -> скрипт чистит мусор
3. Шаг 2: PyEQEq (создаем колонку в cif-файле с зарядами)
4. Шаг 3: RASPA


Структура: 

RASPA_tests/
├── run.sh                       (Скрипт запуска)
├── convert_to_raspa.py          (Скрипт обработки)
├── simulation.input.template    (Шаблон настроек - код на RASPA)
├── combine_movie.py             (Нужен для визуализации симуляции в Ovito Basic - совмещает каркас мофа и газ, создаст FULL_MOVIE.pdb)
├── build_forcefield.py          (ОСОБО НЕ НУЖЕН, ДЛЯ ПРОБЫ, Используется только один раз, чтобы добавить поле UFF GarciaPerez2006 из библиотек в локальную папку ForceField - если файлы там уже есть, выполнять не нужно)
├── void.input.template          (ПОКА НЕ РАБОТАЕТ, Шаблонный файл RASPA конкрутно для гелия, чтобы посчитать HeliumVoidFraction)
├── MOF/                         (ПАПКА ДЛЯ НАШИХ СТРУКТУР)
│   ├── MOF5.cif
│   └── Any_Other_MOF.cif
└── ForceField/                  (ПАПКА ДЛЯ СИЛОВЫХ ПОЛЕЙ И ГАЗОВ)
    ├── force_field_mixing_rules.def
    ├── pseudo_atoms.def
    └── force_field.def

В папке Version1 лежит первая рабочая версия 
(без добавления газа в рабочую директорию и без PyEQEq + там все должно лежать в корне рабочей директории, никаких папок)


ЗАПУСК: ./run.sh <MOF_NAME>.cif <GAS_NAME>
Пример: ./run.sh MOF5.cif CO2

Инструкция для пользователя:
1. Поместить .cif файл с каркасом в папку MOF/.
2. Убедитесь, что в папке ForceField/ лежат 3 необходимых .def файла (правила смешения и псевдоатомы): 
   force_field_mixing_rules.def, force_field.def, pseudo_atoms.def.
3. (Один раз) Сделайть скрипт исполняемым: chmod +x run.sh
4. Запуск: ./run.sh <MOF_NAME>.cif <GAS_NAME>
!!! Если хотим что-то поменять в input файле RASPA, меняем в simulation.input.template, а не simulation.input !!!


Результаты:
1. Output/System_0/ - текстовый отчет о симуляции (лог-файл)
    На что обратить внимание: Average loading absolute — сколько молекул влезло (моль/кг или шт/ячейку)
                              Average loading excess — избыточная адсорбция (для сравнения с экспериментом)
                              Heat of desorption — теплота адсорбции (насколько сильно молекулы прилипают)
2. Movies/System_0/ — Визуализация (включено при Movies yes в simulation.input.template)
    Запускаем в Ovito: Framework_...pdb — каркас MOF. Он обычно записывается один раз (так как жесткий).
                       Movie_..._Component_...pdb — «пленка» с молекулами газа. В одном файле записано много кадров подряд.
3. Restart/System_0/ — Сохранения
    Если поставили расчет, но он случайно прервался, RASPA может записать сюда бинарный файл с точным положением и скоростями всех молекул.
    После можно перезапустить симуляцию с флагом RestartFile yes, и она продолжится ровно с того места, где прервалась, а не с начала.
4. VTK/System_0/ — Продвинутая графика (Карты плотности)
    Если включить настройки (WriteVTKGrid), RASPA посчитает не просто "где летают молекулы", а построит 3D-карту:
    - Где молекулы бывают чаще всего (облака вероятности).
    - Карту энергетических ям.
    Эти файлы открываются в программе ParaView. Это нужно для красивых картинок в научные статьи.

Заметки по коду:
1. В simulation.input.template в строчке HeliumVoidFraction 0.29 стоит рандомное значение доли пустого объема. Для каждого MOF оно будет своим.
    Чтобы было точно можно добавить в скрипт подсчет этого числа для текущего MOF.
2. Проблема поставить pyeqeq на mac, на Linux ставится без проблем. На mac работаем без электростатики.
